# x87 extended-precision emulation (`port/sim/x87.[ch]`)

Icy Tower 1.5.1 was compiled by GCC 4.4 for i386 with x87 floating point, and
the process ran with control word `0x037F` (MinGW CRT `_fpreset` = `fninit`):
64-bit significand precision (PC=11), round-to-nearest-even, all exceptions
masked. Gameplay intermediates stay in 80-bit registers and are rounded to
`double`/`float` only at the stores GCC emitted. Replays hold only inputs, so
a port built for SSE2 or ARM must reproduce those exact rounding sequences.
Call sites express each gameplay FP operation through this module, following
the original machine code instruction by instruction.

## What is emulated

| x87 instruction | function |
|---|---|
| `fild dword/qword` | `x87_from_i32`, `x87_from_i64` (exact) |
| `fld dword/qword` | `x87_from_f32`, `x87_from_f64`, `*_bits` variants (exact; subnormals normalised, SNaN quieted) |
| `fadd` `fsub` `fmul` `fdiv` | `x87_add` `x87_sub` `x87_mul` `x87_div` (PC=64, RN) |
| same at PC=53 / PC=24 | `x87_add_pc(a, b, X87_PC53)` etc. (full 15-bit exponent range, as the hardware does) |
| `fsubr` `fdivr` `fiadd` `fidivr` `fadd dword [m]` ... | swap operands and/or wrap the memory operand in `x87_from_*`, since loads are exact |
| `fchs` `fabs` | `x87_neg` `x87_abs` (sign bit only, also on NaN) |
| `fst(p) qword/dword` | `x87_to_f64` `x87_to_f32` (RN; overflow to inf, gradual underflow, NaN truncated and quieted); `x87_rnd_f64/f32` = store + reload |
| `fistp` with RC=chop (C casts) | `x87_to_i32_trunc` `x87_to_i64_trunc` |
| `fistp` with RC=nearest | `x87_to_i32_rn` `x87_to_i64_rn` |
| `fucom` + `fnstsw` | `x87_fucom` (C3<<2 &#124; C2<<1 &#124; C0: `>` 0, `<` 1, `==` 4, unordered 7), `x87_fucom_sw` (status-word bits 0x4500, so `test $0x45,%ah` is `(sw >> 8) & 0x45`) |
| C relational operators | `x87_cmp` (-1/0/1, 2 = unordered), `x87_lt/le/gt/ge/eq` (false when unordered), `x87_ne` |

Masked-exception results are exact: overflow gives a signed infinity, tiny
results are denormalised and then rounded once (extended denormals; at PC=53/24
the rounding point is the precision boundary of the shifted significand, as
on the hardware), `x/0` for `x != 0` gives a signed infinity, and invalid
operations (`0/0`, `inf/inf`, `0*inf`, `inf-inf`) give the real indefinite
(`0xFFFF:C000000000000000`). NaN operands propagate quieted: a single NaN is
returned; for two NaNs the QNaN wins over an SNaN, otherwise the larger
significand, and for equal significands the positive one. `fistp` of NaN,
infinity or an out-of-range value gives the integer indefinite
(`0x80000000` / `0x8000000000000000`). Exact cancellation gives `+0`,
`-0 + -0 = -0`, and `x + 0` is still rounded to the precision control.

Not emulated: `fsqrt`, `fprem`, `frndint`, transcendental and `fscale`
instructions, directed rounding modes for arithmetic, and exception flags (the
game reads none; it never calls a math-library function). Pseudo-denormals are
accepted as values; unnormals, pseudo-infinities and pseudo-NaNs are treated
as invalid operands (indefinite / unordered), as on post-387 CPUs, but these
encodings never arise from this API and are not hardware-verified.

## Representation and algorithms

`x87` is the exact register image: `uint64_t m` (explicit integer bit at bit
63) and `uint16_t se` (sign bit 15, biased exponent bits 14..0, bias 16383),
so results can be compared bit-for-bit with hardware and with `long double`
dumps. The implementation is C11 with 64-bit integer arithmetic only: no host
floating point, no `long double`, no x87 instructions; `float`/`double` are
reinterpreted through `memcpy`.

- Operands are unpacked to (class, sign, unbounded exponent, normalised
  64-bit significand); denormals are normalised with a negative exponent.
- Results are formed as a 128-bit significand `hi:lo` with the leading bit at
  bit 127 and handed to one rounding routine (`round_pack`): if the exponent is
  below the normal range the value is shifted right with a sticky "jam" bit,
  then it is rounded to nearest-even at bit 64 (PC=64), 53 or 24 using the
  bits below the rounding point plus the sticky bit, with carry-out
  renormalisation, then checked for overflow.
- Add/sub: the smaller operand is aligned inside 128 bits with a jammed
  sticky bit (any exponent difference, including > 128). Subtraction with an
  exponent difference <= 1 is exact, so massive cancellation is exact; with a
  larger difference at most one normalising shift is needed and the jam bit
  stays below the rounding point.
- Mul: exact 64x64->128 product. The portable path uses four 32x32->64 limb
  products (verified default); `-DX87_USE_INT128` switches to `__int128`.
- Div: restoring long division producing 64 quotient bits plus a guard bit;
  the sticky bit is "exact remainder != 0", so rounding is exact (ties are
  only possible at PC=53/24 or in the denormal range, and are covered).
- Stores to `double`/`float` round the significand once, including the
  subnormal range, directly from the 64-bit significand (no double rounding).
- `fistp` rounds by chop or nearest-even at the binary point and range-checks
  the rounded magnitude.

## Verification (`tests/port/unit/test_x87.c`)

The test runs 32 operations x 9 operand distributions (288 blocks). On
x86/x86-64 GCC/Clang, where `long double` is the x87 format, each case is
also executed on the FPU with inline asm (`fadd/fsub/fmul/fdiv %st(1),%st`,
`fstpl/fstps`, `fistpl/fistpll` under an explicit RC, `fildl/fildll`,
`fldl/flds`, `fchs/fabs`, `fucompp; fnstsw`) under control word `0x037F`
(`0x027F`/`0x007F` for the PC=53/24 blocks) and compared bit-for-bit; the C
relational operators are checked against the compiler's own `long double`
comparisons.

Operations: add/sub/mul/div at PC 64, 53 and 24; neg; abs; fucom +
relational operators; to_f64; to_f32; to_i32/i64 with chop and with RN;
from_f64/f32 (raw bit patterns, including subnormals, SNaN/QNaN, inf);
from_i32/i64; and chains kept in extended precision: `(a*b)+c`,
`(a*b)+c -> fst qword` (one asm block on the register stack),
`(a-b)/c -> fst dword`, `double(a) + double(b)*c -> fst qword`,
`fild i / fild j` (divisor often 0), `fucom(fild i / fild j, a)`,
`(int)((a*b)+c)`.

Distributions: random doubles (all exponents, subnormals, short fractions);
game-like values (positions 0..1000 and down to -200000 with fractional parts,
velocities -30..30, the game constants 0.7, 0.9, 0.3, 0.8, 0.2, 1.4294484665,
12.0, 12.2, -0.2, 65535.0f..., float-stored values, and extended intermediates
such as products and multiply-adds; screen-sized integers and cross products
with zero divisors); random extended values with patterned low bits (all
rounding positions: exact tie, tie +- 1, all ones, zeros); large exponent
differences (0..200); near-cancellation (same and neighbouring binade);
constructed ties (short significands placed at the PC=64/53/24 rounding point,
products with pc+1 significant bits, exact quotients); the full exponent range
with extended denormals, products/quotients landing at the underflow and
overflow edges, `x - x` and NaN pairs with equal significands, zeros,
infinities, QNaN/SNaN and indefinite; integers (fild) including INT_MIN/MAX
and zero divisors; values at or next to rounding boundaries of int, double and
float (n + 1/2 +- ulp, double/float half-ulp +- ulp, 2^31, 2^63, the
double/float overflow and subnormal edges).

Results on this host (MinGW-w64 GCC 12, x86-64, Release):

| run | cases | mismatches |
|---|---|---|
| default (`test_x87`), 200 000 per block | 57 600 000 (1.8 M per operation) | 0 |
| `--cases 5000000 --seed 12345` | 1 440 000 000 (45 M per operation) | 0 |
| i686 (MinGW32 GCC, 32-bit limbs on a 32-bit CPU mode), `-O0`, `-O3 -march=native`, `-DX87_USE_INT128` builds, default run | 57 600 000 each | 0 |

Sensitivity was checked by mutation: each of 17 deliberate single-point bugs
(ties away from zero at PC=64 or PC=53/24, sticky bit ignored, `x + 0` not
rounded to PC, NaN-selection rules, lost jam bit in denormalisation, missing
division sticky bit, `-0` from exact cancellation, store tie rule, `fistp` RN
tie and range limits, unquieted SNaN loads, PC-rounding of denormals, signed
zero comparison, `x/0`, float subnormal stores) makes the test fail, both in
native mode and in vector-only mode.

### Hosts without x87 (ARM, MSVC, Android)

`tests/port/unit/x87_vectors.h` holds, for each of the 288 blocks, an FNV-1a
hash of the emulator results of the first 200 000 cases and the first 4
results verbatim, recorded from a clean native run. The operand generator is
integer-only and deterministic (every random draw is its own statement, since
C leaves argument evaluation order unspecified), so any host regenerates the
same 57.6 M cases and checks them against the hashes; `--no-native` forces this
mode on x86. MSVC 14.50 (x64, portable `clz` path) passes it. After changing
the generator or adding operations, regenerate with
`test_x87 --gen-vectors tests/port/unit/x87_vectors.h` on an x86 host (refused
unless the native comparison is clean).

## Using it at call sites

Mirror the original instruction stream: keep every value the original kept
on the FPU stack as an `x87`, round with `x87_to_f64`/`x87_to_f32` exactly
where GCC emitted `fst(p)` to a `double`/`float`, and reload with
`x87_from_*`. A branch compiled as `fucom; fnstsw; test $0x45,%ah; je L`
("jump if st0 > st1 and ordered") is `if (x87_fucom(st0, st1) == 0) goto L;`.
Do not substitute `x87_rnd_f64` for values that stayed in registers, and do
not fold constants: `0.7` loaded from a `double` constant is
`x87_from_f64(0.7)`, and a `float` constant is `x87_from_f32(...)`.
